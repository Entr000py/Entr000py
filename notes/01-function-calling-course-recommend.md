# 关键词匹配失败之后，课程推荐怎么收成 Function Calling 条件

健身课程推荐里，用户很少把需求说成标签。更常见的是一句口语：「膝盖不太好，想练核心，最好 20 分钟，别太跳。」关键词匹配在这种句子上会失败：要么一个词都对不上，要么只抓住「核心」，把跳跃课、长课时课一起推出来。推荐列表看起来有结果，但和用户刚说的约束是反的。

## 失败长什么样

失败不是「没有召回」，而是召回偏了。

- 伤病部位被丢掉，核心词还在，于是伤膝用户看到需要跳跃的核心课。
- 时长、人群、难度没有进入筛选，排序只按课程热度。
- 候选不够时，系统把整句条件放宽，核心训练目标也一起松了。
- 用户点过「不感兴趣」之后，下一轮仍推同一门课。

所以要改的不是再堆同义词，而是让模型先交出一组可执行的筛选条件。

## 改了哪一步

对话意图和课程标签用同一套字段：训练目标、身体部位、课程人群、时长、难度。模型通过 Function Calling 把这句话收成结构化条件，而不是把原句丢给关键词。

```json
{
  "goal": "核心",
  "body_parts": ["核心"],
  "avoid_body_parts": ["膝盖"],
  "audience": null,
  "max_minutes": 20,
  "level": null
}
```

后面的检索和排序只消费这组字段。

1. 用测评等级和学习进度先做候选筛选，再按目标匹配、难度接近程度加权排序。
2. 候选不足时，只放宽次要偏好，例如时长上下浮动、人群画像放宽。训练目标和需要避开的身体部位保持不动。
3. 「不感兴趣」写成抑制条件，同一门课在后续轮次里降权，而不是只从当前列表里删掉。

Function Calling 在这里的作用是把自然语言收成过滤器。推荐偏不偏，取决于这组字段和课程标签是不是同一套，以及哪些字段允许放宽。

## 结果怎么量

线下用 5000 条独立标注请求看 Precision@4：前 4 个推荐里，被标成符合用户目标且不违反约束的比例。改完之后，Precision@4 从 68% 到 84%。

线上用设备级 A/B 看推荐后 30 分钟内是否开始训练。开练率从 20% 到 23%，提升 3 个百分点。开练率只说明推荐有没有被用起来，不能代替 Precision@4。两个数回答的是两件不同的事。
